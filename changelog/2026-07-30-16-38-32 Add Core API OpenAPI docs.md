# Add Core API OpenAPI docs

Added a generated OpenAPI document for Primordia Core route-action endpoints at `/api/core/openapi`. The document is built from the same CLI route metadata used by the existing Core API command-list endpoint, including route paths, path/query parameters, named request fields for each command argument/option, streaming response hints, and web API-key bearer authentication. Its OpenAPI `servers` entry now respects forwarded public origin headers and `NEXT_BASE_PATH`, so preview instances advertise URLs like `/preview/{threadId}` instead of the internal localhost server. Operations are tagged by top-level Primordia subcommand so Scalar groups the sidebar by areas like `thread`, `server`, and `jobs`, use the command name as the operation summary, and keep the CLI description as the operation description; the internal `--json` CLI switch and short CLI aliases are no longer exposed as caller-settable API details because buffered actions apply JSON automatically while API docs use stable long field names.

Core route metadata now distinguishes read-only query commands from mutations. Query commands are exposed and documented as `GET` endpoints with arguments/options in query parameters, while mutation commands remain `POST` endpoints with arguments/options in JSON request bodies. Empty string values for string options are rejected before command execution, so malformed streaming requests such as `lines=` return a proper 400 JSON error instead of a 200 response containing CLI stderr. Terminal error responses set `Connection: close`, and log endpoints only keep the response open when `follow=true` produces a successful streaming response.

Core route-action request parsing now accepts documented top-level JSON or multipart fields named after command arguments and options while preserving the older `args`/`options` compatibility format. CLI usage failures that happen under automatic `--json` now return the validation message from the CLI's JSON stdout in the API `msg` field instead of falling back to a generic command-exited message.

Changed `/api-docs` to render the Core OpenAPI Scalar reference, replacing the older app REST API documentation page. The Scalar bundle is loaded lazily behind a lightweight page shell so the preview server no longer blocks first response on compiling the full API reference package during development. The temporary `/test-pages/core-api-test` route was removed because Core API exploration now lives at the canonical docs URL.
